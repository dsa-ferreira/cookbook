# cookbook 0.3.0 update

0.3.0 tightens the MCP tool inputs. Tools now reject arguments they don't
declare, and `list_recipes` swaps its ingredient arguments for two new lists.
For the infra side this is only a new image tag plus new WARNING log lines.
There are no changes to settings, ports, the schema or the healthcheck. The
interface change does break clients (see `clients`).

```yaml
handover_update: 1
service: cookbook
from: 0.2.0
to: 0.3.0

before: []

changes:
  - change: changed
    path: components.api.image
    value: album.lan/cookbook:0.3.0

after:
  - Tell the user the release is live, so they can update agent prompts and saved tool calls (see clients).

verify:
  - >-
    curl -s https://cookbook.lan/mcp -H 'Authorization: Bearer <key>'
    -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream'
    -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"list_recipes","arguments":{"ingredients":["chickpeas"]}}}'
    →  200 and JSON with "isError":true and result.structuredContent
    {"error":"validation_error","message":"unknown argument: ingredients",...}.
    On 0.2.0 the same call succeeds, so this proves the new image is running.
  - >-
    The same request with "arguments":{"all_ingredients":["chickpeas"]}
    →  "isError":false, and result.structuredContent contains an
    "unmatched_ingredients" list
  - >-
    After the first rejected call, `docker logs` on api shows a line like
    `WARNING cookbook.mcp: tool list_recipes rejected: args=['ingredients'] details=[...]`

clients: >-
  Breaking for MCP clients. list_recipes no longer accepts `ingredients` or
  `ingredient_match`. It takes `all_ingredients` (the recipe has every listed
  name) and `any_ingredients` (the recipe has at least one), which combine with
  AND. Any argument a tool doesn't declare now fails with validation_error
  instead of being silently dropped. Claude Code and open-webui read the new
  schemas from tools/list, so nothing needs re-registering. Agent prompts or
  saved calls that use the old argument names have to change.
rollback: >-
  Pin album.lan/cookbook:0.2.0 again. The schema is unchanged, so no restore is
  needed. Clients already switched to all_ingredients/any_ingredients would
  have those arguments silently dropped by 0.2.0 (unfiltered results), so
  revert the agent prompts too.
```

## Details

- **New log lines.** Every tool call rejected with `validation_error` is
  logged at WARNING on the `cookbook.mcp` logger. The line gives the tool
  name, the names of the arguments sent, and the error details (location,
  type, message). Argument values are left out, with one exception: an
  unknown unit code appears in its error message, e.g.
  `unknown unit 'handful'`. The default log level is INFO, so these lines show
  up without any configuration. Counting them shows how often agents send
  malformed calls.
- **Schema size.** Every tool argument now has a description, so the
  `tools/list` response is somewhat larger. It still fits well within the
  proxy defaults (1m body, 60s).
- **No downtime steps.** There are no migrations; deploying is a normal
  container restart.
